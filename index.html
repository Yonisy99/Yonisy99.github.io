网站部署指南

本指南将详细介绍如何将此个人网站免费部署到 GitHub Pages、Netlify 或 Vercel，以及域名绑定和常见问题解决方案。

部署准备

在开始之前，请确保您已经准备好以下内容：

  • 本 HTML 文件（命名为 index.html）。
  • 一个 Git 仓库（GitHub, GitLab 或 Bitbucket）。
  • （可选）一个自定义域名。

GitHub Pages 部署

1. 创建仓库

在 GitHub 上创建一个新仓库。为了获得用户主页，仓库名称必须为 用户名.github.io。

2. 上传文件

将您的 index.html 文件上传至仓库根目录。

3. 启用 Pages

进入仓库 Settings → Pages。在 "Build and deployment" 下，选择 Source 为 Deploy from a branch，并选择 main 分支和 / (root) 目录，点击 Save。

4. 访问网站

等待约 1-2 分钟，访问 https://用户名.github.io 即可查看。

Netlify 部署

1. 注册与准备

访问 Netlify.com 并使用 GitHub 账号注册登录。确保代码已推送到 GitHub。

2. 导入项目

点击控制台上的 Add new site → Import an existing project。选择 GitHub 并授权，然后选择您的仓库。

3. 构建设置

对于纯静态 HTML，保持默认设置即可（Build command 留空，Publish directory 为 /）。点击 Deploy site。

Vercel 部署

1. 导入项目

登录 Vercel，点击 Add New → Project。选择您的 Git 仓库并点击 Import。

2. 配置与部署

Vercel 会自动检测框架。对于静态站点，无需修改配置，直接点击 Deploy 按钮。

常见问题及解决方案

部署后出现 404 错误？

可能原因及解决：

  • 文件名大小写不匹配（Linux 服务器区分大小写）。
  • 缺少 index.html 文件。
  • 如果是 SPA，需配置服务器回退规则（如 Netlify 的 _redirects 文件）。
CNAME 配置失败怎么办？
  • 检查是否与 A 记录冲突（同一主机名不能同时存在 A 和 CNAME）。
  • 根域名通常不支持 CNAME，需使用 ALIAS 记录或 301 跳转。
  • 请确保 DNS 记录值完全复制自托管平台提供的地址。
HTTPS 重定向循环？

通常由源站配置错误引起。如果在 CDN 后面，请检查源站是否强制 HTTPS 且端口配置正确。建议在 CDN 设置中开启 "Edge Certificates" 并关闭源站的强制跳转。
